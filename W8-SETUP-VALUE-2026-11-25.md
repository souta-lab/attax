## Why this mechanism (and what was excluded)

Night diagnosis (`bench-results/night-2026-11-24/README.md`): attax
converts 1.07 atk/line vs Hoiko 1.27, TSD 226 vs 294 over 30 games; the
working hypothesis is that Hoiko's depth-14 search reads T-spin setups
ahead. Per lanechat #8498, touching the conversion side by re-weighting
existing tables values is excluded (collides with W7 and value sweeps
are already registered as banned), and W6 (the coarse B2B-state shader
term, tabf(171)) was rejected 12-18 — this variant is neither: it is a
new detector, not a re-weight and not the B2B term.

Chosen candidate: **(a) Φ credit for a T-slot one move from completion.**

## Mechanism

`near_tslot32(c, len)` (in `persistent/pfl_r15_serve.comp`, injected by
`gen_r15_serve.py` step 6b) returns 1 when a board holds a T-slot shape
exactly **one added cell** away from a complete `best_tslot32` slot:

- Same centre column `x` (1..8) and stem height `hx = height(c[x])` as
  the complete-slot test; the stem cell and the three flat-row cells
  must be empty (they are the T's own cells — a filled one cannot be
  fixed by adding a cell, so the candidate is disqualified, not counted).
- Defects are counted against the complete-slot conditions:
  a missing lower corner cell (either side, at `hx`) counts 1;
  a missing overhang (neither roof cell present at `hx + 2`) counts 1.
- Both roofs present (no open side) or a blocked open side disqualifies:
  removing a cell is not one placement away.
- Exactly 1 defect → near. A complete slot has 0 defects and is not
  near, and the leaf term is additionally gated on `tslot == 0`, so the
  credit is disjoint from the complete-slot weight `tabf(155)`.

Leaf wiring (both rules profiles, like the `tslot` term in `dot` — the
Hoiko/TBP path is the guideline profile, so an S2-only gate would never
fire there):

```glsl
float setupNear = (tabf(172) != 0.0 && tslot == 0)
    ? float(near_tslot32(c32, len)) * tabf(172) : 0.0;
float value = acc + (sScale * tabf(168)) * (dot + b2bState + phiEx + setupNear);
```

## Flag / tables

- Gate = tables slot **172**, previously unused (0.0 in both the config-O
  and W7 files; verified by reading all 180 doubles). W8 tables set it
  to **75.0** — half the W7 single-line tslot weight (150), i.e. a
  one-away setup is priced at half of the completed single it is one
  cell from. This is an initial mechanism value, not a tuned one; no
  sweep was run.
- New `gpu/tables.bin` sha256:
  `3c8fa328f0ffc892547f587b97e4043c4c33fba56636878c8bbfc13277cfacb3`
  (verified: header unchanged, exactly one of 180 doubles differs from
  the W7 file — index 172, 0.0 → 75.0).
- `PINNED_TABLES_SHA256` (`tools/s2-lab/gpu-player.ts`) and the sha
  mentions in `gpu/README.md` / `gpu/DESIGN.md` follow the new pin,
  following the W7 landing's procedure.
- **Flag OFF is bit-identical to W7 by construction**: with slot 172 at
  0.0 the ternary skips the scan entirely and the added term is exactly
  0.0 appended to the same float sum (the shipped value canonicalises
  0.0 anyway). Restoring the W7 tables file restores the W7 lineage
  byte-for-byte in this slot. This is a structural argument, not a
  measured gate result — the GPU equivalence gate still has to be run
  on the PC before any promotion, as with W7.

## Desk estimates ([見積], no measurement)

- **Judgment change rate [見積]**: the credit is
  75 × tabf(168) (0.97) ≈ 72.8 points × sScale on a qualifying leaf,
  vs ≈145.5 for a completed single-line slot and ≈13.6 per unit of
  bumpiness (W7 tabf(150) −14 × 0.97). Sibling-leaf value gaps in a
  96-wide beam are routinely in the tens of points, so the term is
  large enough to reorder leaves whenever a near slot is present, and
  exactly zero otherwise. [見積] Root decisions change on roughly
  3–10% of placements in mid-game positions where T setups are being
  built — basis: the size comparison above only; no games, no probe
  runs were made.
- **Latency [見積]**: the scan runs only when slot 172 ≠ 0, once per
  child evaluation, over 8 centre columns with ~10 bit tests each —
  the same shape as the already-paid `best_tslot32` scan, so the eval
  stage gains at most about one extra tslot scan. [見積] Decision
  latency impact ≤ +2%, likely under +1% (the eval stage is dominated
  by the dedupe atomics, not feature scans). Not measured; the pfserve
  bench on the PC is the arbiter.
- **Strength [見積]**: not estimated. The mechanism targets the
  diagnosed setup-reading gap, but no seed band was consumed and no
  number here is evidence of strength.
